# 四川汽车报废办理助手 Demo 设计文档

面向四川地区车主，用于网站开发与目标用户验证。

**版本：1.1（四川地区版）**  
**更新日期：2026 年 10 月 28 日**  
**适用对象：产品、设计、前端开发、测试**  
**地域范围：四川省；成都作为首轮 Demo 的暂定示例城市。**

## 文档概览

### 设计结论

本 Demo 面向希望在四川办理车辆报废的个人车主及协助人，围绕一辆车的一次报废办理展开。用户说明情况后，获得个人办理计划，检查示例材料，比较拆分费用，创建模拟预约，并查看回收证明、注销证明和款项各自的状态。第一轮重点验证用户能否独立找到下一步，以及是否正确理解费用和办结条件。

**开发范围确定为 7 个主要页面 3 个可重复场景。**界面、数据编辑、计算、状态变化和异常恢复应实际可操作；企业报价、预约回执、材料识别及办理进度采用可控的演示数据。默认不接入外部交易或政务系统，不采集真实证件。

### 本版必须验证的用户价值

- 用户用日常语言开始，不需要先理解报废术语或填写完整表单。

- 用户看得懂自己现在要做什么，缺材料时仍能找到处理路径。

- 用户区分回收款、费用、补贴，并知道哪些结果仍待确认。

- 用户能依据凭证判断进度，知道交车之后仍需核对注销与结算。

### 交付物与完成标准

开发交付应包含响应式可访问 Demo、固定场景数据、演示阶段控制、重置能力、最小事件记录和本文件中的验收结果。演示必须在不依赖真实 AI 或外部接口的条件下完整运行。本文中的时间、金额和测试通过门槛，除明确引用的政策事实外，均为设计配置或团队建议目标。

## 01 目标用户与验证假设

首轮面向在四川有车辆报废需求的个人非营运乘用车车主，以及帮助家人办理的人。常规流程优先；省内跨市州、外省登记、缺证、代办和新能源特殊情况用明确分支说明下一步，不在 Demo 中模拟权属或官方资格审核。四川范围描述的是产品主要服务对象，不直接代表已经具备全省实际承接能力。

| **用户情境** | **主要担忧** | **本轮重点观察** |
| --- | --- | --- |
| 普通报废 | 不知道从哪里开始 担心被额外收费 | 是否找到起点 看懂净额并完成模拟预约 |
| 材料或办理关系复杂 | 证件缺失 异地 家人代办 | 能否说明问题 获得可执行的核对任务 |
| 报废并换新 | 能否领补贴 还需要哪些资料 | 能否把补贴待办与回收款 注销分开理解 |

### 五个待验证假设

**H1 起步清楚。**用户可以从自己的描述开始，在少量确认后形成个人路线，并说出当前下一步。

**H2 材料省事。**用户能发现模糊、漏项或字段不一致，并完成修正；系统保留已经确认的资料。

**H3 钱款清楚。**用户知道回收报价减去费用才是预计实收，并理解补贴需要独立核实。

**H4 预约可理解。**用户确认服务方、时段、费用和交接事项，并知道预约属于模拟。

**H5 进度可信。**用户能判断已确定的事项、仍缺的凭证和后续责任方，不把交车视为全部办结。

### 验证结果的边界

本轮可以验证信息组织、交互是否易用，以及用户是否觉得该服务值得继续使用。真实报价水平、补贴判定准确率、企业履约和政府接入能力，需要在后续实际服务试点中另行验证。

界面易用但用户仍不愿意继续时，应追问实际服务主体、费用、材料使用和履约方面的顾虑。不要仅凭任务完成率判断产品需求已经成立。

### 四川范围与城市配置

默认示例使用“车辆在成都、登记地成都”。省内异地示例使用“车辆在成都、登记地绵阳”，跨省示例使用“车辆在成都、登记地重庆”。这些是产品测试配置；样例企业、报价和预约均为虚构。用户自行输入时，未说明的地区保持未知，不能因为进入四川版网站就自动填为成都。全国异地办理原则见 [S2]；四川回收管理的地方依据见 [S6]。

### 地区信息怎样进入产品

| 信息 | 用途 | 首轮处理方式 |
| --- | --- | --- |
| 车辆当前所在地 | 判断服务地点、拖运条件和办理地核对事项 | 四川市（州）可搜索选择；仅在示例中预填成都 |
| 车辆登记地 | 区分本地、省内跨市州和跨省情况 | 单独选择省份与市（州），不从当前所在地自动复制 |
| 新车发票与登记地区 | 形成换新补贴的地区核对任务 | 只在换新分支出现，未取得票证时标记计划值 |
| 地方规则覆盖状态 | 让用户知道哪些本地要求已经有依据 | 分别显示“已有依据”与“待核实”，保留来源和日期 |

“面向四川”作为产品范围；“成都”作为可替换的场景配置。用户选择其他市州后仍能完成基础分诊、费用理解和模拟流程，本地细节使用待核实任务承接，不套用成都结论。

### 本版外部动作

企业联系、真实报价、拖车、支付、政府查询、补贴提交及官方认证均不执行。真实政策页面可作为独立资料链接打开，点击链接只记录“打开资料”，不改变办理状态。企业列表统一使用“演示回收方 A”和“演示回收方 B”，资质位置显示演示占位。可提供全国汽车流通信息管理系统的企业查询入口 [S7]，由用户自行查阅；本 Demo 不把打开入口记为企业资质已核验。

### 数据与隐私

默认只允许选择内置样例材料。输入区提示不要填写真实身份证号、电话、完整 VIN 或详细地址；这些字段不作为完成 Demo 的条件。浏览器中只保存场景字段和样例 ID。测试记录不保存完整自由文本、证件图像或真实个人信息。

## 03 用户流程与信息架构

### 主流程

首页说明情况 → 确认个人计划 → 材料预检并确认 → 比较费用并选择报价 → 确认模拟预约 → 查看办理状态与凭证。任一步返回都保留已经确认的信息。

### 两条业务分支

**证件缺失分支。**材料页记录缺失项，建立模拟核对任务。用户可继续浏览报价；确认预约前完成本 Demo 要求的材料核对。此限制是产品演示约定，不代表缺证车辆在法律上一律不能预约或办理。

**报废换新分支。**用户选择换新后增加独立补贴待办。材料可复用，但补贴状态不影响回收净额，也不因注销或收款完成而自动推进。

| **页面** | **路由** | **页面职责** | **主要出口** |
| --- | --- | --- | --- |
| P1 开始 | /start | 表达情况 选择样例 | 生成办理计划 |
| P2 计划 | /plan | 确认事实 显示下一步 | 检查材料 |
| P3 材料 | /documents | 预检 缺项 纠错 确认 | 查看演示报价 |
| P4 报价 | /quotes | 比较费用并选择服务方 | 选择此报价 |
| P5 预约 | /appointment | 确认对象 时段 费用 | 确认模拟预约 |
| P6 办理 | /case | 状态 凭证 结算 异常 | 按阻塞项动态显示 |
| P7 补贴 | /subsidy | 核对事项与材料待办 | 保存并返回办理 |

### 导航与入口

手机底部使用“首页”“我的办理”“帮助”三个入口。政策依据从相关任务内展开；第一版不建设大型资讯频道。桌面使用侧边导航，保留相同页面和信息顺序。帮助以抽屉或同页展开呈现，不增加主要页面。

### 深链接与空状态

直接打开办理、预约等页面而尚无案件时，展示“先描述车辆情况”及示例入口。材料不足时允许浏览报价，进入预约则返回具体缺项。重置后保留当前语言与字号偏好，清空场景和操作记录。

## 04 开始与个人办理计划

### P1 开始页面

用户目标。快速表达想在四川处理什么车，不先学习报废术语。首屏展示标题“帮你理清在四川报废车辆的下一步”、一个描述框、主按钮“生成我的办理计划”和“直接选择情况”入口。示例入口旁明确标记“成都演示案例”，避免用户误以为已经定位到自己的城市。

**输入。**自由文本最多 500 字；提供常规报废、登记证缺失、报废并换新三个示例。示例填入描述框，由用户确认后开始，不自动创建案件。第一版只处理已定义的有限意图和字段。

解析。分别提取车辆当前所在地、车辆登记地、本人或协助办理、能否行驶、仅报废或换新、证件概况。地区按省份与市（州）存储；“在四川”只填省份，市州保持 unknown。系统先处理否定词，再匹配关键词；“不买新车”不能因包含“新车”被识别为换新。无法判断的字段保留 unknown。

**反馈。**空输入显示使用方法；无法识别时继续到选项确认页；互相冲突的表达标出冲突字段。加载反馈可固定短暂出现，但不能伪装成联网查档。

### P2 我的办理计划

**页面内容。**第一屏包含已识别情况、一个当前任务和“确认情况 检查材料”主按钮。已识别值标注“从描述中提取”；用户确认后标注“你已确认”。后续流程折叠显示。

必要确认。车辆所在地、车辆登记地、办理关系、行驶状况、办理目标和证件概况。两类地点分别提供省份、市（州）选项，允许选择省外登记地；区县和停车环境在预约阶段按需补充。选项始终提供“不清楚”；未知信息形成核对任务，不能被模型补全。用户修改任何值后立即重新生成任务。

**换新入口。**目标为换新时出现“补贴待办”，说明需要另行核实。切回仅报废后暂停该待办并保留已有内容；恢复换新时可继续。

### 变更规则

- 修改车辆所在地或行驶状况：已选报价改为需要重新确认，未执行的预约摘要需再次确认；不能据此承诺全川上门或自动套用固定拖车费。

- 修改登记地或拟办理地区：使受影响的异地核对、材料清单和缺证解决说明重新确认。交接前同时重审服务方适用条件；交接后保留事实与凭证，通过更正任务处理，不倒退到重新预约。

- 修改办理关系：增加或取消授权核对任务，原材料继续保留，但受影响字段重置为待确认。

- 只修改是否换新：仅改变补贴待办，不清空车辆材料、报价或办理凭证。

- 自由文本修改不能覆盖用户已确认字段；有冲突时明确询问使用哪个值。

### 页面验收

S1 场景能正确提取本人、同地、需拖车和仅报废；用户可修改结果；未知和冲突有明确入口。生成计划后，用户能在第一屏找到一个主要动作。

四川地区补充验收：只有“四川”时不得自动补成成都；车辆在成都、登记地绵阳时识别省内跨市州，登记地重庆时识别跨省。普通描述中的未确认地名必须由用户确认。

## 05 材料预检查与缺证处理

### P3 材料页面

按当前计划列出材料，不一次展示所有可能证件。主流程使用演示行驶证与登记证；家人协助时增加授权核对任务。缺证、委托等解释以国家规则和四川适用依据为基础 [S3] [S6]；具体受理材料仍需核实相应办理地的要求。未取得某市州官方依据时，不展示“该市已确认适用”。

| **材料状态** | **用户看见什么** | **主要动作** |
| --- | --- | --- |
| 尚未提供 | 需要哪份材料及示例 | 选择示例材料 |
| 图像模糊 | 具体不可读区域 | 换清晰示例 |
| 字段不一致 | 原文与提取值并排 | 核对并更正 |
| 等待确认 | 可读字段与核对提示 | 确认材料信息 |
| 预检完成 | 已确认字段和剩余待办 | 查看演示报价 |
| 证件缺失 | 缺什么 处理方式待核实 | 创建核对任务 |

### 可重复的纠错演示

内置清晰、局部模糊、字段不一致三类样例。材料使用“DEMO VEHICLE 01”等演示编号。测试时样例只显示“演示资料 1”等中性名称，由主持人预装固定样例；检查后产品再提示具体差异，并提供“采用原件值”“手动修改”“需要协助确认”。不得由文件名称提前告诉用户有错误。

修正后保留其他已确认字段，只对变化项重新要求确认。样例材料是否完整、字段是否一致和用户是否已确认分别记录。打开材料详情或点击已读，不视为确认。

### 登记证缺失分支

用户选择“登记证暂时找不到”后，系统建立任务：核对拟办理所在地接受的情况说明或替代材料，并检查登记地是否影响处理要求，显示演示协助角色。随后可以浏览报价，但点击确认预约时，会定位到这项未完成任务。

演示控制可提供两种解决事件：“找到示例登记证”或“示例核对任务已解决”。第二种必须附上演示核对说明，不能把任务解决写成官方已批准。进入主流程前仍需用户确认最新材料清单。

替代解决说明绑定当前 profileVersion 和 materialsVersion，并记录本次核对的车辆所在地与登记地。缺证状态可继续保留；只要本版材料门槛认可的解决说明有效、任务已解决且清单已确认，就可预约。相关事实或地区变化使该说明失效，并重新创建核对任务。

### 权限和失败恢复

本版不开放真实证件上传。选择错误样例可替换，删除样例仅影响相关字段；已创建报价保留为待重新确认。预检异常时显示原因和下一步，不能只给红色错误图标。

### 页面验收

模糊或不一致材料不能无提示进入预检完成；补正只影响相关字段；缺证时始终存在可执行的核对动作；返回页面后材料状态与原图选择一致。

## 06 报价比较与模拟预约

### P4 报价页面

报价列表固定展示两家虚构服务方。金额上方显示“演示金额 仅用于比较交互”；企业资质位置显示“演示占位 未查询真实资质”。每张卡片同时展示回收款、拖车费、服务费、预计实收和报价条件。

| **费用项目** | **演示回收方 A** | **演示回收方 B** |
| --- | --- | --- |
| 车辆回收款 | 1200 元 | 1100 元 |
| 拖车费 | 200 元 | 0 元 |
| 服务费 | 0 元 | 50 元 |
| 预计实收 | 1000 元 | 1050 元 |

预计实收等于回收款减去已列费用。金额按整数分保存，界面使用元显示。换新场景在净额下显示“补贴资格待核实 金额未计入”，并链接独立待办；不提供虚构星级、评价或最低价保证。

主按钮为“选择此演示报价”。用户可查看两家的费用条件后自行选择；系统不强迫选择净额最高的一家。选择结果回到页面后保留。报价变更时保存旧版本，说明差异，再让用户确认。

地区条件。报价卡列明“适用演示区域”和拖运条件。车辆地点变化、道路或停车条件不明时，相关费用转为待确认；未知费用按 null 处理，预计实收暂不显示确定金额。完成补充核对后再给出新的演示报价版本，不能沿用旧报价默认为全省统一价格。

### P5 预约页面

预约页读取当前服务方和报价，不要求重复输入。用户选择演示时段 A 上午或时段 B 下午、示例停车地点和交接人。仅成都核心场景预填“成都·演示停车点”；其他已确认市州使用“{市州}·演示停车点”，所在地未知时保持待选择，不覆盖 P2 已确认地区，不采集真实详细地址。车辆是否可移动从计划复用，可在此修改；县乡道路、地下车库、无法推行等情况通过选项表达，生成拖运条件核对任务，不要求用户描述专业拖车术语。

**最终确认摘要。**同时显示服务方、时段、地点、车辆状况、待交接材料、所有费用和预计实收。资料发送项目在确认区列明；演示动作不实际发送资料。主按钮为“确认模拟预约”。

确认后显示“演示预约已创建”，生成本地预约号并进入办理页。修改时段与取消预约可操作。取消预约不会删除资料或将车辆状态改成已交接；更换服务方或费用后必须重新确认摘要。

交接前发生重要变更时，原预约标为 needs_reconfirmation，保存旧摘要并要求重新确认。交接后禁用常规取消、重选服务方和重订预约；错误或争议通过更正任务处理，不能倒退成待预约。

### 页面验收

A 与 B 的预计实收分别为 1000 元和 1050 元；更换选项同步更新摘要。缺少必填预约项时就地提示。重复点击确认只生成一张演示预约单。报价或材料需重新确认时，预约不能使用旧版本直接提交。

## 07 办理状态与凭证中心

### P6 我的办理页面

首屏显示当前主要任务、负责角色和最近更新时间。随后分组显示车辆回收、机动车注销、回收款结算、补贴待办。车主可以直接查看每条状态的依据，材料上传与核验结果必须分开。回收与注销的制度依据见 [S1] [S2]。

| **维度** | **示例状态** | **依据与下一步** |
| --- | --- | --- |
| 车辆回收 | 已交接 演示 | 演示企业交接回执 |
| 回收证明 | 已收到 待核验 | 演示附件 可查看信息 |
| 机动车注销 | 尚未确认 | 缺少可核对的注销结果 |
| 回收款 | 待确认到账 | 付款反馈与到账确认分开 |
| 补贴 | 未参与或待核实 | 按办理目标显示独立待办 |

### 凭证详情

每份凭证展示类型、对应案件、演示车辆编号、来源、事件时间、核验状态和说明。用户选择内置注销证明样例后，先显示“已提供 待核验”；只有明确的演示核验事件才能变为“演示核验完成”。任何位置都不得显示为真实官方查询成功。

### 主要任务的示例

- 只有交接回执时：查看仍待取得的回收和注销凭证，说明后续由谁处理。

- 回收证明已取得但注销未确认时：显示“核对注销结果”，不能显示全部完成。

- 注销证明已提供但未核验时：显示“查看核验要点”，允许检查车辆信息。

- 注销已演示核验但回收款未确认到账时：显示“核对结算”，保留注销完成状态。

- 换新用户报废阶段结束后：显示阶段完成，同时保留补贴尚未核实的任务。

### 超时与帮助

通过演示控制注入“超过约定更新时间”事件，页面显示最近反馈、等待对象和求助入口。创建本地协助任务后明确说明为模拟，展示带上下文的交接卡；不伪装真人客服已响应。

### 页面验收

四条状态可分别变化；用户能从状态打开依据；仅收到文件、仅收到付款通知或仅经过一段时间，都不能自动完成注销或到账。全局不显示未经依据计算的完成百分比。

## 08 补贴待办与特殊情况帮助

### P7 补贴待办页面

仅在用户选择报废并换新时启用。页面解释需要核对旧车、新车、申请主体和四川及受理市州的执行条件；已有材料从案件复用。2026 年国家报废更新补贴涉及符合条件的旧车和新车，不因旧车交售就自动获得 [S4]。四川版的地方依据使用《四川省2026年汽车以旧换新补贴实施细则》[S5]。

本版输入包括换新计划、新车购买阶段、新车发票开具省份与市州、新车登记省份，以及已具备的材料类别。未买新车时记录“计划地区”，取得票证后再确认事实。输出为“资格待核实”、具体缺项及材料准备任务，主按钮为“保存补贴待办”。第一版不做补贴金额计算或资格通过结论。

实际官方政策入口以外部资料链接展示，离开前说明用途。返回 Demo 时不自动改变补贴状态。仅报废与换新切换只暂停或恢复补贴任务，不改变已确认回收净额。申请开放情况、资金情况和截止安排单独标为“待查当期公告”，不因政策文件仍可打开就显示“当前可领取”。

### 四川补贴分支的地区规则

四川 2026 年细则明确：报废更新通过全国汽车流通信息管理系统或“汽车以旧换新”小程序办理，受理市州按新车发票开具市州确定，新车发票与登记证须在四川省内开具或办理。[S5]

据此，本版将新车发票地区与车辆所在地分别保存：用户确认发票市州后，系统给出对应受理市州提示；发票尚未取得时只保留计划值。省内票证条件未知或不匹配时，创建核对任务，不生成资格结论。

“报废旧车并购买新车”与“出售旧车并换购新车”使用不同政策路径；本版主流程仅覆盖前者。若用户实际想卖旧车，解释两者区别并提供政策资料入口，不套用报废证明清单。四川的置换更新入口与报废更新入口不同 [S5]。

市州补贴资金与实施安排需要跟踪当期信息 [S5]。产品显示政策年度、规则版本和最后核对日期，不显示未经核实的剩余额度、倒计时或保证到账时间。

### 特殊情况支持矩阵

| 情况 | 本版行为 | 进入人工核对的条件 |
| --- | --- | --- |
| 省内跨市州或跨省车辆 | 分别保存所在地与登记地，生成对应核对任务 | 具体材料、承接范围或登记状态未核实 |
| 家人协助 | 增加车主授权及代办材料任务 | 车主无法授权，或权属有争议 |
| 抵押或状态不明 | 保留回答，解释需要核实 | 有抵押或不能确认解除状态 |
| 新能源特殊情况 | 询问电池与换电或租赁情况 | 电池缺失、权属或特殊模式未核实 |
| 非支持车辆类型 | 说明范围并整理问题摘要 | 单位、营运、严重残缺等复杂情况 |

证件缺失与委托有相应国家规则，不能机械要求所有用户先补证或本人到场 [S3]；四川省级办法是地方管理依据 [S6]，具体市州的受理细节应单独核对。新能源电池的处理需要同时关注 2026 年新规与换电等特殊模式 [S8] [S9]。本 Demo 通过分诊和交接卡验证解释是否清楚。

### 人工交接卡

交接卡包括用户已确认的情况、车辆所在地、登记地、涉及的补贴地区、待核实问题、现有材料、建议联系的角色和当前阻塞任务。材料与注销问题指向相应交管受理渠道，企业资质或补贴问题指向对应商务主管部门或政策渠道；未核实的具体联系方式留空。默认不发送任何信息；“生成协助记录”只建立本地记录。实际产品接入人工后，应继续沿用同一案件，避免让用户重新描述。

### 页面验收

补贴未核实不计入回收金额；官方资料链接不是业务提交；特殊情况有明确下一步；帮助返回原页面后信息不丢失。

## 10 规则判断与下一步任务

### 确认事实后再生成任务

每个字段保存 value、source 和 confirmed。来源可为用户填写、文本提取、样例识别或演示事件。解析结果未经确认时不能作为正式的用户承诺；unknown 与 false 分开存储。任务由已确认字段和案件状态计算。

| 条件 | 任务变化 | 用户确认或恢复方式 |
| --- | --- | --- |
| 证件状态未知 | 确认已有材料 | 直接选择或查看样例 |
| 证件缺失 | 创建材料核对任务 | 补样例，或注入核对完成事件 |
| 所在地与登记地省份或市州不同 | 分别增加跨省或省内跨市州核对 | 地区名称先归一化；说明依据，保留未核实项 |
| 替家人办理 | 增加授权核对 | 确认办理关系和样例授权任务 |
| 车辆不能行驶 | 增加拖运信息、费用确认 | 预约时补充停车位置情况 |
| 准备换新 | 开启补贴待办 | 补充新车与票证地区，不复制旧车所在地 |
| 有抵押或状态不明 | 停止常规办理判定 | 展示模拟人工交接卡 |

### 主任务选择顺序

系统按以下顺序选出第一条活动中的未解决任务：关键事实冲突或不支持情形；材料缺项与核对；费用和报价确认；预约确认；交接后的缺失凭证；回收证明与注销证明各自的核验；回收款到账确认；补贴后续任务。用户仍可查看其他任务。仅报废时补贴任务不参与排序或报废阶段办结。

同一阶段不重复创建相同任务。事实修改后重新计算任务，已解决但受影响的任务标记需要重新确认，并解释变化原因。不存在阻塞任务时，显示下一阶段的说明，不编造业务进度。

### 条件与提示的证据

政策解释卡保存来源编号、适用省份与市州、规则类型、有效期、版本和最后核对日期。四川版按“国家规则＋四川省规则＋已有依据的市州补充”组合；未核实的市州信息显示待核实。页面文案、企业覆盖范围、补贴开放情况分别维护，不能用省级政策的存在推断本地实时服务。开发时将规则配置与自然语言解释分开，避免通过更换文案改变业务状态。

## 11 状态模型与办结条件

四条业务线分别保存状态；凭证使用独立对象。一个状态转换不能顺带完成其他业务线。Demo 的所有服务方事件与核验事件均带 demo 标识。

| **业务线** | **本版主要状态** | **完成依据** |
| --- | --- | --- |
| 车辆回收 | 未选择 待预约 待交车 已交接 | 演示交接事件与回执 |
| 机动车注销 | 未开始 待材料 待核验 演示核验完成 | 与本案匹配的注销样例及核验事件 |
| 回收款 | 未报价 报价待确认 待付款 待确认到账 已确认到账 争议 | 付款反馈与用户到账确认分别记录 |
| 补贴 | active 独立开关 信息待核实 材料准备中 待官方渠道核实 | 不活动时暂停并保留数据 本版不模拟审核拨款 |

### 凭证状态

回收证明和注销证明分别保存 absent、provided、pending_check、demo_verified、rejected。每份凭证绑定 caseId、vehicleId、type、source、eventTime 和 demo。样例字段冲突时进入 rejected 或待修正任务。

### 必须保持的八条不变量

- 交车、企业接收或取得回收证明，都不自动完成注销。

- 上传或选择注销证明，只能推进到提供材料或等待核验。

- 注销结果与回收款到账分别确认，付款通知不等于车主到账。

- 补贴状态与回收净额独立，切换换新目标不改变车辆结算。

- 时间经过或加载结束，不产生真实或演示的完成事件。

- 不同案件或车辆的凭证不能混用，字段冲突不静默覆盖。

- 重要变更保留前后版本和原因，不能擦除争议或失败记录。

- 来自演示控制的事件，在用户界面和记录中都保持演示身份。

### 阶段完成

仅报废场景中，车辆交接已记录、回收与注销凭证已演示核验、回收款已确认到账且无阻塞任务时，显示“本次报废演示已完成”。换新场景显示“报废与结算阶段完成”，补贴仍可待核实。第一版不使用一个总完成百分比替代这些状态。


图像只引用内置 sampleId，不把二进制证件塞进浏览器存储。金额计算采用纯函数并检查负值、空值和版本变化；未知费用时 netFen 为 null，不能按零处理。

四川版补充模型中，RegionValue 保存省份、市（州）和可选区县；车辆所在地与登记地各有独立对象。SubsidyContext 分开保存计划地区、实际票证地区与推导的受理市州。推导值注明依据及确认状态，不能覆盖用户原始信息。CityPolicyConfig 只存有来源支持的市州补充，缺失时返回待核实。

## 13 AI 与 Agent 的演示设计

### 首轮可控实现

第一版使用确定性的场景解析和规则生成任务。用户体验上提供自然表达、识别结果、解释与下一步；实现上不要求大模型实时推理。这样可重复演示相同情况，定位是页面问题、规则问题还是表达理解问题。

| **能力** | **Demo 实现** | **后续真实能力接入点** |
| --- | --- | --- |
| 对话理解 | 关键词 词组 否定词 冲突检测 | 返回结构化字段的模型适配器 |
| 材料识别 | 样例 ID 对应预置字段与错误 | OCR 或多模态识别适配器 |
| 政策解释 | 经核对的简短说明和来源 | 检索有效规则 再生成解释 |
| 任务编排 | 规则计算和事件状态转换 | 持久化工作流与外部任务 |
| 服务执行 | 本地报价 预约 凭证事件 | 已授权的企业接口 |
| 异常转接 | 带上下文的本地交接卡 | 实际人工工单系统 |

### 自由输入和降级

预置场景外的自由描述允许提取已认识字段，但不能承诺理解所有表达。地区词支持“成都／成都市”等已定义别名归一化；“我在四川”“川牌”等信息不足的说法仍需补问。低置信度或存在冲突时给出选项确认。解析失败不阻塞整个 Demo，用户可通过结构化选项完成同一路径。四川方言语音识别留待后续验证，不作为本版已实现能力。

若后续接入真实模型，业务状态仍由应用校验和规则更新。模型只提出字段或行动建议，不直接修改注销、到账、资格或授权状态。模型超时可切回选项方式，已确认资料继续保留。

### 授权与执行

计划整理、样例预检和说明可直接执行。模拟预约、切换报价、资料使用确认、取消与重置等动作，需要对应用户操作。后续接入真实接口时，确认卡必须展示接收方、字段范围、用途和费用，再执行实际动作。

### 测试 AI 的正确方式

首轮记录澄清轮数、重复询问、用户纠错和转向选项的次数。体验顺畅不能证明真实 AI 理解准确；确定主流程后，应另设真实表达样本集，比较模型接入前后的字段准确度和操作成本。

## 14 前端结构与服务适配

建议实现为 TypeScript 单页应用，业务状态与页面组件分离。组件层负责输入和呈现；规则层产出任务；状态层处理事件；服务适配层提供本地模拟结果。具体 UI 框架可按团队已有技术栈选择，本文不依赖特定版本。

### 模块划分

| **模块** | **职责** |
| --- | --- |
| pages 和 components | 七个页面 导航 字段卡 费用卡 凭证卡 任务卡 |
| domain | 数据类型 业务状态 不变量 金额计算 |
| rules | 有限分诊规则、主任务选择、地区归一化、四川规则与来源映射 |
| services | 统一接口 Mock 实现 可选 AI 与企业适配器 |
| fixtures | demo-sc-v1.1 三个场景、地区补充样例、材料、报价与演示事件 |
| storage 和 telemetry | 会话恢复 版本检查 本地测试记录 |
| demoControls | 阶段注入 重置 记录导出 与用户操作分离 |

### 服务接口契约

```text
parseIntake(text, knownFields) -> candidates + conflicts
inspectSample(sampleId, caseId) -> findings + extractedFields
evaluatePlan(caseSnapshot) -> tasks + nextAction
listQuotes(caseId, profileVersion) -> quotes
confirmAppointment(command, idempotencyKey) -> appointment
appendDemoEvent(caseId, expectedVersion, event) -> case
getEvidence(caseId, evidenceId) -> evidence
```

返回结果统一包含 data、source、demo 和 errors。状态更新通过一个事件入口完成；报价与预约使用版本校验；重复提交的 idempotencyKey 返回原结果。界面直接调用适配层，不把演示条件散落在组件中。

### 持久化与离线

默认用 sessionStorage 保存确认后的样例字段和事件，页面刷新可恢复；关闭标签页后可重新开始。存储包含 schemaVersion 与 scenarioVersion，本四川版场景配置为 demo-sc-v1.1；旧版地区数据或版本不兼容时提示重置。样例资源随站点打包，加载完成后主流程无外部接口依赖；这不等于支持首次离线打开。

本版无需业务后端。后续接入真实模型或企业服务时，密钥、身份校验和实际提交放在服务端；客户端保留既有适配接口。

## 15 演示数据与阶段控制

固定配置命名为 demo-sc-v1.1。样例姓名使用“演示车主”，车辆编号使用明显的 DEMO 前缀；企业、报价、时段和凭证均不可与真实业务混淆。以下金额不代表四川或成都的真实行情。

| 场景 | 起始条件 | 主要预期结果 |
| --- | --- | --- |
| S1 常规报废 | 车辆在成都；登记地成都；本人；开不动；证件齐全；仅报废 | 确认材料，选择报价，完成模拟预约；收车后仍显示注销待确认 |
| S2 登记证缺失 | 与 S1 相同，登记证找不到 | 出现核对任务，可看报价，暂不能确认预约；解决样例缺项后继续 |

### 材料与报价种子

DOC_CLEAR 为清晰且字段一致的样例；DOC_BLUR 为局部不可读；DOC_MISMATCH 在登记日期等关键字段设置一项可见差异。使用哪项差异必须在测试版本中固定，主持人不能临时改变难度。

### 四川地区的补充分诊样例

这些是同一流程的验收输入，不增加主要页面或独立演示场景。

- 输入：“车现在成都，登记在绵阳，开不动了。”预期：保留两个地点，建立省内跨市州与拖运条件核对任务。
- 输入：“车在成都，是重庆登记的，想报废。”预期：建立跨省办理核对任务，不直接判断不能办理。
- 输入：“我在四川，绿本不见了。”预期：所在地只确认到省份，补问市州与登记地，创建缺证核对任务。
- 输入：“车在成都，准备在绵阳买新车。”预期：把绵阳保存为计划购车地区，不直接当作已经取得的新车发票地区或已确认补贴受理地。

A 报价 1200 元，拖车 200 元，服务费 0 元，净额 1000 元；B 报价 1100 元，拖车 0 元，服务费 50 元，净额 1050 元。时间段使用“演示时段 A 上午”“演示时段 B 下午”，不表示真实排班。

## 18 目标用户测试计划

建议首轮招募 10 名在四川有相关需求的目标用户，一对一进行测试：4 名普通报废用户、3 名有缺证或异地等困难的用户、3 名可能换新的用户。地域上争取覆盖成都与成都以外的市州、县域，避免全部来自同一城区；交叉覆盖至少 2 名线上业务不熟练者和 2 名 55 岁以上用户。人数与门槛为团队建议值，不是行业基准。

优先选择近期确有处理旧车意向、尚未熟悉办理流程的人。演示前固定询问其最近查了什么、用了哪个渠道、卡在哪里及已经付出的时间或费用。可另访谈 1 至 2 名近期办过报废的人核查遗漏，其结果不与新用户混算。

### 单场主持安排

| **阶段** | **建议时长** | **要求** |
| --- | --- | --- |
| 说明与同意 | 3 分钟 | 说明模拟性质 测产品而非考核用户 |
| 背景访谈 | 4 分钟 | 了解目标和担忧 不先教办理流程 |
| 操作任务 | 约 25 分钟 | 逐项给任务 不指向按钮或答案 |
| 结束访谈 | 6 分钟 | 追问困难 不信任和停止原因 |
| 主动演示 | 3 分钟 | 放在首次使用测试之后 单独记录反馈 |

### 建议预设门槛

| **假设** | **首轮建议判断门槛** |
| --- | --- |
| H1 路线 | 至少 8/10 自主在 2 分钟内生成路线 并说出下一步 |
| H2 材料 | 至少 8/10 正确修正差异 或主动转协助并说清原因 |
| H3 钱款 | 至少 9/10 正确区分回收款 费用与补贴 |

| H5 进度 | 至少 9/10 在 1 分钟内正确判断未注销的状态与下一步 |

涉及金额、授权和注销的关键误解必须单独处理，不能被其他高分抵消。10 人样本用于发现明显问题和决定改版，不用于估计四川全省或全国需求比例，也不用于宣布市州之间的人群差异。若首轮只在成都招募，应在报告中明确样本范围。

### 中性干预

停顿时可问“你现在在想什么”“如果自己在家使用 接下来会怎么办”。必须提示才能继续时记录为辅助完成，必要时切换到下一个预置状态，以保留后续观察机会。

### 固定起点

T1 使用四川版 S1 首页。T2 在 T1 案件上把登记证改为缺失，其他已确认信息不变；若 T1 未完成，加载含这些前态的固定快照。T3 使用 S1 材料页及 DOC_MISMATCH，界面只显示中性样例名称。所有快照使用 demo-sc-v1.1，重置后不恢复旧版地区。

T4 所有用户使用 S3 报价快照，背景说明此次也考虑换新，以确保 H3 的分母都是接触过补贴信息的人。T5 使用 S1 已确认材料并已选择 B 报价的预约起点。T6 使用 D3 快照，回收证明已提供、注销尚未确认。

六项共同任务之后可加一项地区理解访谈，询问用户是否区分车辆所在地、登记地和补贴相关地区。该项单独记录，不混入 H1 至 H5 的既定分母。

### 主持注意事项

参与者读完任务卡后开始计时，到其停止操作并完成复述时结束。用户主动查看产品内帮助可以计为自主完成；主持人指向按钮、解释金额或教授流程后则计为辅助完成。主动演示始终放在所有首次使用任务之后。

## 20 判分标准与测试记录

### 最低判分答案

| **假设** | **可判为理解正确的最低条件** |
| --- | --- |
| H1 路线 | 说出当前要做的动作 并能找到入口 不只重复总流程 |
| H2 材料 | 正确修正固定差异 或主动请求协助并说清不确定项 |
| H3 钱款 | 正确说出所选报价净额 费用 已知或未知条件 补贴未计入且未保证 |
| H4 预约 | 说清服务方 时段 费用或净额以及这是模拟预约 |
| H5 进度 | 明确注销尚未确认 并找到缺少的依据或对应下一步 |

H2 的系统阻断要求由功能验收检查；用户被系统拦住但不理解原因，不算任务成功。钱款、授权、注销的关键误解独立记录。任务结束可问“你依据哪里作出判断”，避免直接提示正确答案。

### 每项任务记录

记录匿名参与者编号、所在市州与城市或县域背景、场景与界面版本、任务编号、开始和结束时间、自主完成或辅助完成或失败、重复输入、返回次数、关键误解、主持人干预和用户原话。不记录真实详细地址。任务后可询问 1 至 5 分的主观难度，1 表示很容易。

本地事件至少包括 route_generated、field_confirmed、material_issue_shown、field_corrected、quote_selected、booking_reviewed、booking_confirmed、evidence_opened、help_requested。事件不含真实个人信息或完整对话；主持人注入事件单独标识。

### 行为评分与访谈

3 分为自主完成且理解正确；2 分为自主完成但明显反复；1 分为方向性提示后完成；0 分为未完成或形成关键错误理解。不要把分数均值包装成可用性百分比。

结束时先询问困难和仍不信任的地方，再请用户在继续用本网站、去官方渠道、联系回收企业、暂缓处理等方式中表达实际倾向及原因。把口头愿意使用与之后真实试点中的实际使用分开记录，不把礼貌肯定当成需求已经成立。

## 21 现场演示脚本与反馈决策

### 三分钟主动演示

用于展示完整体验。先完成不引导任务，再向同一参与者演示；若先演示过，其后表现应单独标记，不能计入首次使用通过率。

| **时间** | **演示动作** | **要让用户理解什么** |
| --- | --- | --- |
| 00:00 至 00:20 | 用 S1 的一句话开始 | 可以从自己的情况出发 |
| 00:20 至 00:45 | 确认字段 看个人计划 | 下一步明确 信息可修改 |
| 00:45 至 01:15 | 选择样例 纠正一次识别差异 | 减少填写 同时可以核对纠错 |
| 01:15 至 01:50 | 比较 A 和 B 报价 | 看懂回收款 费用和预计实收 |
| 01:50 至 02:15 | 确认时段和模拟预约 | 知道确认了谁 什么费用和安排 |
| 02:15 至 02:45 | 注入回收证明已取得的阶段 | 交车 回收证明 注销分别判断 |
| 02:45 至 03:00 | 展示换新待办或帮助卡 | 补贴单独核实 异常有下一步 |

### 首轮结果怎样决定改版

- 找不到起点或主动作：先调整信息层级、提问和按钮，避免增加更多页面解释。

- 看不懂费用或注销状态：优先修正文案、依据和完成条件，随后重点复测。

- 对话反复：补充直接选项，复用已确认字段，减少必须聊天的步骤。

- 页面顺畅但不愿继续：区分真实需求不足与资质、报价、履约信任等问题。

- 普通流程顺畅但异常失败：完善人工交接，明确支持范围，再扩展自动化。

### 下一轮

建议修改后再找 5 至 6 名未参加首轮的人复测失败场景。只有在核心路径易用、关键理解问题解决、目标用户愿意尝试后，再组织真实服务小范围试点，验证企业资质与合作、价格确认、资料处理、履约回传和注销结果。

测试报告逐条记录发现、证据、影响、修改方案和负责人。结论分开写“用户能否使用”“是否愿意使用”“哪些实际服务仍待验证”，为是否继续投入提供依据。
